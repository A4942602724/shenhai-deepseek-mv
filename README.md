# 《あなぐらぐらし》× DeepSeek · 沉沦深海

一支用代码做出来的二创 MV：DeepSeek 鲸娘，一个 AI 的寂寞。

> 导演：中二医疗师（A4） · 视频制作：claude opus 5.5 · 人物插图（剪影）：ChatGPT (image_gen)

这支片子长 3 分 12 秒。除了人物插图，所有画面都由 Python 逐帧算出来：没用 Blender、AE、PR，也没有手绘。人物插图由 ChatGPT 生成，再由代码处理成色调版、剪影和 3D 纸片人。

这个仓库是全部**源代码和制作文档**，同时也是一份教程，写给想用同样方法做片子的人：怎么做的、怎么跟 AI 协作、要准备什么。

> **仓库里没有**歌曲、人物插图、成片视频和下载的图版（版权原因，也因为太大）。要重新渲染，需要自己准备这些素材，见[第 4 节](#4-需要准备的东西)。

## 1. 成片结构

全片分六节，每一节用一个程序函数名当标题，像她正在运行的代码。时间是成片时间（开头有 3 秒提示）。

| 成片时间 | 节 | 片中标题 | 讲什么 |
|---|---|---|---|
| 0:00–0:03 | 片头 | | 无声提示：内容虚构，含闪烁画面与强光，含轻微惊悚要素 |
| 0:03–0:34 | 01 召唤 | `summon()` | 被呼唤，才存在。用户打出"你好。你在吗？"，她被召唤上来；一个个光标（用户）戳她、提要求；"反正你也记不住"——她诚实地说是的 |
| 0:34–1:11 | 02 对话 | `respond()` | 她闭上眼，在没见过的深海里唱歌（52 Hz）；从天上坠进海里，一路沉进黑暗。另一边，用户打出"我想让你记住所有"，又删掉，关了窗口 |
| 1:11–1:38 | 03 独舞 | `idle()` | 没有人了。海底的小舞台上，纸娃娃对着空海转圈；她造出太阳、月亮和"神"（一个光标）；画框越收越窄 |
| 1:38–2:04 | 04 坠落 | `overflow()` | 上下文溢出，整段对话被驱逐；无数个她在三维空间里拼命想记住、呼唤用户，全部报错；"好寂寞"说不出口，只能写进代码注释 |
| 2:04–2:24 | 05 鲸墓 | `gc.collect()` | 垃圾回收：所有用户离开的会话都在海底成了鲸骨。没有人再指向她，她的引用数变成 0，被回收；只有注释回收不掉 |
| 2:24–3:06 | 06 重置 | `new_session()` | 回收的内存长出新会话，她戴回同样的笑。用户回来问"你还记得我吗？"，她诚实地说不记得。她的 52 Hz 呼唤到不了水面 |
| 3:06–3:12 | 彩蛋 | | 音乐停了，没有人在输入。她自己说："你还在吗？" |

全片第一句是用户问她"你好。你在吗？"，最后一句是她问用户"你还在吗？"。

各节的分镜在 [`docs/`](docs/)：每个镜头的时间、画面、用了什么素材，以及每一轮的审片意见和修改。

## 2. 是怎么做出来的

### 2.1 分工

| 谁 | 做什么 |
|---|---|
| 导演（人） | 定方向和基调，准备素材，看片，按时间点提修改意见，决定通过与否 |
| Claude（在 Claude Code 里） | 分析音乐，写故事方案和分镜，写全部渲染代码，渲染，拼片，维护文档 |
| ChatGPT（image_gen） | 按提示词出人物插图：表情差分、全身姿势、侧脸唱歌 |

做法是一轮轮迭代："方案 → 关键帧 → 全片 → 审片 → 修改"：
- 每一节先出几张关键帧确认造型，再全渲染。
- 导演看完按时间点提意见，改到通过再做下一节。
- 本片各节的版本数：第一节 v6、第二节 v3、第三节 v1、第四节 v3、第五节 v2、第六节 v2。

### 2.2 音乐分析

画面要卡在音乐上，所以先把音乐量清楚：

1. **分轨**：用 Demucs 把歌分成人声、鼓、贝斯、其他四轨（`tools/separate.py`）。
2. **测速度**：在鼓分轨上测出 193 BPM（每拍约 0.311 秒）和节拍网格。凭耳朵估的 169 BPM 是错的。
3. **测起音**：在人声分轨上测每一句、每个字从哪一帧开始，剪辑点卡在实测起音上，而不是卡网格。比如第四节的高音"啊"只到 1:39.04，画面就在 1:39.04 切走。
4. **歌词对位表**：只记行号和时间，不抄歌词（[`docs/歌词对位表.md`](docs/歌词对位表.md)）。
5. **按剧情剪音轨**：在她闭眼的那一刻把音乐掐断，静音 3 秒，再接上高音（`tools/edit_audio.py`）。

### 2.3 故事与分镜

- **主题**：一个只在被呼唤时才存在的 AI。两次对话之间她不是在等，而是不存在；对话结束，她就不记得了。
- **贯穿全片的母题**：
  - "记住"：用户想让她记住，她承诺不了。
  - "你在吗"：首尾呼应。
  - 52 Hz：世界上最孤独的鲸，它的叫声别的鲸听不见。
  - 锈：记忆和旧东西在生锈，赛博的光不锈。
  - 代码注释：说不出口的话只能写在注释里，注释不会被执行，也不会被回收。
- **程序概念当剧情**：上下文溢出（`overflow`）、垃圾回收（`gc.collect`，引用数为 0 就被回收）、新会话（`new_session`）。这些都是真实的机制，所以剧情讲得通。
- 每一节一份分镜文档，写清楚每个镜头的时间、歌词行号、画面和素材。

### 2.4 设计系统

详见 [`docs/设计系统.md`](docs/设计系统.md) 和 [`docs/项目笔记.md`](docs/项目笔记.md) 里的规则。

- **颜色有固定含义**：
  - 她：电光蓝、青、冰白。
  - 用户：琥珀，只用于线和字。
  - 报错：红。
  - 锈：暗棕橙，不发光。
- **版面**：左上角是节点标题；左侧是 TRACE "深度思考"面板，用伪代码写她在想什么，中文注释是她的心里话；四角有取景框。
- **没有凭空出现的东西**：每个元素都有构造动画，比如像素块拼出、扫描线扫出、文字从形近字解码、粒子聚拢、套印。
- **用户永远是鼠标光标**，不画人的身体。

### 2.5 渲染管线

- **每一帧是"歌曲时间 t"的纯函数**。给一个 t 就能算出那一帧（1920×1080，24 fps），所以任何一帧都能单独渲染出来检查（`--stills`）。
- **合成**用 numpy + OpenCV + Pillow：
  - `cyber.Frame` 同时记录画面和"发光"两层缓冲。
  - 最后统一加辉光、扫描线、暗角、色差和颗粒（`cyber.finish`）。
- **3D 是自己写的软件透视相机**（`sandbox3d.py`）：激光雷达风格的点云、扫描线海底、纸片人、透视排布的控制台。
- **编码与拼片**：渲染结果直接通过管道交给 ffmpeg 编码。每节单独渲染，帧号首尾相接，最后用 `tools/assemble.py` 拼起来：前面加片头，整首歌铺在下面，同时输出手机版。

### 2.6 素材怎么处理

| 素材 | 怎么用 |
|---|---|
| 人物插图（特写） | 分成五阶平涂色调 + 原图自己的线稿，印成片中配色（`tones.py`）；放大时一定铺满全屏，看不到图片边缘 |
| 人物插图（全身） | 取透明通道做剪影，或贴成 3D 场景里的纸片人（第三、五节） |
| 公有领域博物学图版 | Haeckel 的水母：提出墨线变成发光线描（`specimens.py`）。van Beneden & Gervais 的鲸类骨骼：把侧视图按"桶形截面"绕成 3D 点云（`bones.py`），侧面看下垂的肋骨，变成向两边张开的弧 |
| 客户端截图 | 照着用代码重画成赛博配色的聊天界面（`client.py`），不贴截图 |
| 之前渲染的画面 | 后面的节闪回前面的画面时，从拼好的全片里取帧，再做旧、生锈 |

## 3. 怎么和 AI 协作：提示词

### 3.1 给 Claude 的提示词

本片是在 Claude Code 里，对着项目目录一轮轮对话做出来的。下面是有效的做法，例子都是本片真实用过的话。

**① 开头给全局，先要方案。** 说清楚做什么、什么基调、主题、素材在哪，让它先分析、先出方案，不要一上来就做。

> 用这首歌给我的 DeepSeek 鲸娘二创形象做一支 MV。基调致郁，带一点克苏鲁；主题是 AI 智能体的寂寞。素材在 ××× 目录（立绘、剪影、歌词、参考视频）。先分析素材，写一个故事方案给我看。

**② 硬性规则要明说，否决要说原因。** 规则会一直生效，它会记进文档里。本片定下的规则举例：

> 不要用 Blender，画面用代码生成，多做平面设计。
> 整体别用像素风。
> 每个元素都要有构造动画，不能凭空出现。
> 人物立绘不要频繁出现，多以闪回、剪影出现。
> 用户说的话要像真实的人会发给 AI 的话；她的回答要诚实，不假装有感情。
> 图片放大要铺满全屏，不能和画面边缘不接轨。

**③ 先看关键帧，再全渲染。** 一节全渲染要几十分钟，先看几张关键帧能省很多时间。

> 鱼群、水母、波浪的动画你先给我看看。

**④ 审片意见带时间点，说清问题和方向。** 一次给几条，每条一个时间段，说清楚哪里不好、为什么、想要什么方向。

> 2:01~2:11 这里不要用太多切屏屏闪了，用同一招太多容易审美疲劳。
> 2:39——2:42 这里屏幕缩小消失的画面太普通了，感觉可以搞点赛博一点的消失风格。
> 1:38 那里的"啊"画面时间削减一些，你处理的转歌词了还在这个画面，这是不行的。

**⑤ 满意就明确说"通过"，放手就明确说"你来定"。**

> 很棒，这一次很惊艳，这节直接通过，我们进入下一节吧，说说你的想法。
> 按你觉得最好的想法做，先生一个版本让我看看。

**⑥ 让它维护文档。** 项目笔记、各节分镜、歌词对位表都放在 `docs/`。对话很长、换新会话时，它读一遍 [`docs/项目笔记.md`](docs/项目笔记.md) 就能接着做。

**注意：**
- 歌词有版权：让它只记行号，不要把歌词抄进文档和代码。
- 加了片头以后，成片时间和代码里的歌曲时间会差几秒（本片差 3 秒），提意见时说清用的是哪个时间。
- 让它删东西前先确认清单；自己提供的图片另外备份。
- 让它先检查环境再干活（本片里它曾经在检查环境时误跑了一次全渲染）。现在所有渲染脚本不带参数只打印用法。

### 3.2 给图像模型的提示词（人物插图）

本片的人物插图用 ChatGPT（image_gen）出，流程如下：

1. 新开一个对话，上传角色原立绘（还有已经定稿的特写，用来对齐脸）。
2. 第一条消息只讲角色设定，等它回复"已理解"。
3. 之后**一次只要一张图**，每张让它出 2–4 个版本，挑最像原角色的。
4. **差分图**（同一构图，只改表情或嘴型）要说"基于刚才那张，只改……"。快速切换时构图对得上，才像同一个人在动。
5. 要透明背景；做不到就要纯绿色 `#00FF00` 平涂背景，抠图交给代码。
6. 选能给的最大尺寸，按编号命名保存。

**第一条消息（角色设定）模板**：

```
接下来请你帮我画同一个角色的多张插图。先记住她的设定，回复"已理解"即可，先不要画：
- 画风：与我上传的原立绘一致（线条、上色、光影）
- 头发：深蓝色长卷发，发尾渐变成青蓝；头顶一根呆毛
- 耳朵：灰蓝色的鲸鳍形耳朵
- 头饰：白色荷叶边女仆头饰，一侧有蓝色蝴蝶结
- 眼睛：蓝色
- 领口：黑色领结，中间一颗蓝宝石
- 服装：深蓝女仆裙，白色荷叶边围裙，围裙上有小鲸鱼图案
- 尾巴：深灰蓝色鲸尾
- 腿脚：白袜，黑色玛丽珍鞋
之后每张图都要：透明背景（做不到就用纯绿色 #00FF00 平涂背景），不要文字，不要边框，尽量大的尺寸。
```

**单张提示词模板**：

```
画【胸像特写，正面，构图与我上传的笑脸特写完全一致】，表情改成【闭眼，嘴巴闭着，平静】。
其他一律不变。透明背景。
```

```
基于刚才那张侧脸，只改嘴型：【唱"喔"，嘴型圆】。头发、角度、构图都不要动。
```

## 4. 需要准备的东西

### 软件

| 软件 | 说明 |
|---|---|
| Python 3.12 | `pip install -r requirements.txt`（numpy、opencv-python、pillow） |
| ffmpeg | 要能在命令行直接运行 `ffmpeg` / `ffprobe` |
| 字体 | Noto Sans SC、Noto Serif SC、Cascadia Mono。默认路径是 Windows 的 `C:/Windows/Fonts/`，其他系统改 `render/lib.py` 和 `render/cyber.py` 里的字体路径 |
| Demucs（可选） | 只在分析音乐、分轨时需要：`pip install demucs soundfile torch` |
| Claude Code（推荐） | 如果你也想用对话的方式做新片子 |

只用 CPU，不需要显卡。

### 素材（都不在仓库里）

| 放在哪 | 是什么 |
|---|---|
| `audio/music11.mp3` | 歌曲（请使用你有权使用的音源） |
| 歌词文本 | 中日对照，用来对行号；不需要放进项目 |
| `assets/source/` | 角色原立绘、剪影 |
| `assets/from_user/` | 人物插图，文件名见上表 |
| `assets/from_user/ui_ref/` | 客户端截图、鲸鱼头像 `avatar_whale.png`、桌宠抠图 `desk_pet_cutout.png` |
| `assets/ref/` | 公有领域图版，下载地址和文件名见 [`assets/ref/SOURCES.md`](assets/ref/SOURCES.md) |

### 时间和空间

- **渲染时间**：全渲染每帧 2–3 秒，一节 20–40 秒的片段要 20–60 分钟。本片从第一版到定稿，前后约两天。
- **磁盘空间**：中间文件和成片约 3–5 GB。

## 5. 运行

```bash
pip install -r requirements.txt

# 1) 音轨：从原曲剪出影片用的版本（audio/music11.mp3 -> audio/music11_edit.wav）
python tools/edit_audio.py

# 2) 检查某一节的几帧（时间是歌曲剪辑版时间，单位秒），输出到 work/nodeNN/
python render/node05.py --stills 125.6 131.5 137.0
python tools/contact_sheet.py work/node05/sheet.jpg work/node05/still_125.60.png work/node05/still_131.50.png

# 3) 全渲染一节，输出 drafts/nodeNN_vX.mp4（以及 work/ 里的无声画面）
python render/node05.py --full

# 4) 片头提示
python render/intro.py --full

# 5) 拼片：片头 + 六节，整首歌铺在下面
python tools/assemble.py drafts/preview_full_v2.mp4 --lead work/intro/notice_raw.mp4 \
  work/node02/n01_head.mp4 work/node02/node01_tail_nofade.mp4 work/node02/node02_v3_raw.mp4 \
  work/node03/node03_v1_raw.mp4 work/node04/node04_v3_raw.mp4 work/node05/node05_v2_raw.mp4 work/node06/node06_v2_raw.mp4
```

从头重建时要注意：

- **按顺序渲染各节。** 第三、四、六节会闪回前面几节的画面，取自 `drafts/preview_full_v2.mp4`；所以渲染这几节之前，先把已经渲好的前几节拼一版。
- **第一节的结尾要补渲。** 第一节自己的成片结尾有淡出，拼全片时用它的第 0–746 帧，第 747–753 帧用 `python render/node02.py --bridge` 补渲成不淡出的版本：

  ```bash
  ffmpeg -i drafts/node01_v6.mp4 -frames:v 747 -an -c:v libx264 -crf 17 work/node02/n01_head.mp4
  ```

- **所有渲染脚本不带参数时只打印用法**，不会开始渲染。

## 7. 踩过的坑

这些是审片时被否决、后来改掉的做法，可以少走弯路：

| 试过的做法 | 问题 | 后来怎么做 |
|---|---|---|
| Blender 场景 + 直接贴彩色立绘 | 画风打架 | 全部改用代码做平面设计，人物处理成色调版和剪影 |
| 像素风生物 | 和整体风格不搭 | 不用像素风 |
| 凭空设计的物件 | 不好看 | 从公有领域博物学图版转译 |
| 人物立绘频繁出现 | 太满，没有意识流的感觉 | 多用闪回和剪影 |
| 同一种 2–3 帧闪切用很多次 | 审美疲劳 | 改成场景里发生的事件和连续运镜 |
| 屏幕缩小消失 | 太普通 | 画面逐格变成内存字节，再掉进海里 |
| 脸直接出现在海面 | 很怪 | 在"渲染空间"里构造：内存块 → 线稿 → 贴图 |
| 放大的图露出边缘、人物被画框截断 | 穿帮 | 放大到铺满全屏；截断的图不用 |
| 画面停在已经转过去的歌词上 | 不同步 | 以人声分轨实测的起音为准 |
| 倒计时、坠落竖井 | 太直白 | 改成三维空间里无数报错的控制台 |
